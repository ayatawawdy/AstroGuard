# AstroGuard – Submission Summary

**Project title:** AstroGuard – Personalized Sleep and Alertness Decision Support for Astronauts

## Abstract

AstroGuard is a research prototype that helps mission staff notice when an
astronaut's alertness may be declining. It does this by comparing that person's
recent sleep and reaction-time performance with their own earlier baseline.
It combines four kinds of data:
- manual sleep logs
- wrist-actigraphy records in the format exported by the existing Actiwatch
  Spectrum device family
- short PVT-inspired reaction-time tests
- optional cortisol values, used as context only

It produces one of four transparent statuses: Normal, Attention Needed,
Rest Recommended or Insufficient Data. Each status shows the evidence and the
rules behind it and gives task-aware advice. Alerts are stored, deduplicated
and acknowledged by humans in a Mission Control dashboard. AstroGuard never
interrupts a task.

The demonstration uses four fictional, synthetic astronaut scenarios. The
Actiwatch import was tested with real, public actigraphy recordings from
research participants on Earth.

## Problem statement

Sleep in spaceflight is often shorter and shifted by mission schedules, and
reduced sleep can slow reactions. Raw wearable data and isolated test scores are
hard to interpret quickly:
- Normal values differ between people.
- Data is frequently missing.
- A schedule change alone is not evidence of impairment.

Mission staff need a signal that is personal, explainable and honest about
uncertainty.

## Proposed solution

AstroGuard turns stored sleep and alertness records into an explainable status:
- It builds each person's baseline only from that person's earlier observations.
- It recommends rest only when reduced sleep and slower reaction-time
  performance occur together.
- It reports Insufficient Data instead of guessing.
- Recommendations depend on the task context (routine, experiment, maintenance,
  safety-critical). For safety-critical work they always defer to Mission
  Control and mission procedures.

## Key functionalities

- Validated SQLite storage for sleep sessions (main sleep and naps, manual or
  wearable), reaction-time assessments with individual trials, optional
  cortisol, actigraphy epochs and alert events. All schema changes are additive.
- An import adapter for Actiware CSV exports (activity, light, off-wrist,
  markers, device sleep/wake, rest intervals). Times are converted to UTC,
  missing data is preserved rather than filled, and personal header fields are
  dropped.
- Four reproducible synthetic scenarios:
  1. normal
  2. shifted sleep schedule without a performance decline
  3. reduced sleep with slower reactions
  4. insufficient data
- A personalized, rule-based analysis with visible thresholds, evidence and data-quality issues.
- Persistent, deduplicated alerts, an acknowledgment record, and a full history.
- A browser-based PVT-inspired reaction-time test, saved only to a separate live
  test profile so it cannot alter the demonstration scenarios.
- A Streamlit Mission Control dashboard. It labels historical, synthetic and real
  data, and shows when data was observed separately from when the alert was created.
- An automated test suite: unit and end-to-end dashboard tests on temporary databases.

## Main innovation

The analysis is personal and explainable, with an honest end-to-end workflow:
- every rule and threshold is shown
- each person is compared only with themselves
- reduced sleep and slower performance must agree before rest is recommended
- missing data is reported explicitly
- persistent alerts are acknowledged by humans
- there is a path for real wearable exports to enter the same pipeline

## Data sources and attribution

- **Real wearable data (Earth participants, not astronauts):** Angelova M.,
  Kusmakar S., Karmakar C., Zhu Y., Shelyag S., Drummond S., Ellis J. (2021).
  *Chronic insomnia and bed partner actigraphy data*. Zenodo record 4961281,
  doi:10.5061/dryad.b8gtht7bh, CC0 1.0. Recorded with a Respironics Actiwatch
  Spectrum Pro in 60-second epochs. It contains no reaction-time, cortisol or
  alertness outcomes.
- **Synthetic data, generated by the team with seeded, reproducible scripts:** the
  four fictional astronaut scenarios, their Actiwatch-like actigraphy, and a
  legacy synthetic health dataset.
- **Background literature:** the PVT (Dinges & Powell, 1985), the brief PVT-B
  (Basner, Mollicone & Dinges, 2011), and spaceflight sleep research using wrist
  actigraphy (e.g. Barger et al., 2014). These are cited for context only.

## Technologies used

Python 3.12, Streamlit, Pandas, NumPy, Plotly, SQLite and unittest. The
reaction-time component is plain HTML and JavaScript, with no Node.js or npm.

## Prototype limitations

- It is not a medical device. It does not diagnose fatigue or replace medical judgment.
- Thresholds are illustrative and have not been validated, in particular not with
  NASA astronaut data.
- The reaction-time test is PVT-inspired: 10 trials with browser timing. It is not
  a validated PVT.
- Actigraphy estimates sleep and wake from movement. It does not measure EEG sleep
  stages, cortisol or reaction time.
- There is no continuous real-time monitoring and no connection to a physical
  watch; stored or imported records are evaluated on demand.
- The demonstration astronauts are synthetic. The real recordings come from people on Earth.
- There is no NASA endorsement, partnership or system integration.

## Future development opportunities

- Expert review and validation of thresholds using appropriate study data.
- The standard 3-minute PVT-B protocol and more robust timing.
- Automated, secure import of crew actigraphy exports.
- Rolling or adaptive personal baselines for long missions.
- Light-exposure and circadian-phase context.
- Integration with crew-scheduling tools, always with human oversight.
